About these checks

Each history bar sums up every check in its period. It is consistent only when consistent checks are a majority and none is a mismatch. A mismatch outvoted by consistent checks makes it inconclusive; otherwise any mismatch shows as a mismatch. Hatching means no probe got a usable answer, so no fingerprint could be taken. The availability view instead colours each period by all of its probes: a failed request or an answer too short to fingerprint counts against availability. A tick above a bar marks a checker version change.

Fingerprints compare responses against reference models. They do not authenticate a provider's backend, and candidate weights are relative within the reference library. Availability counts successful probes from this machine, not continuous uptime.
